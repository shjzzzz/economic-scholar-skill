# Economics Frameworks: mechanism language and prediction templates

Companion to `SKILL.md` Step 2. The framework table in SKILL.md names the pointers; this file gives the wording. **Every citation named in this suite from memory must be verified through `/econ-citation` before it enters a manuscript.** Depth is the conceptual-framework level: assumptions, a stylized model, 1-3 propositions, a testable prediction. This suite does not verify proofs.

## Using a framework (four moves)

1. **Define the object**: what economic quantity does the estimate correspond to?
2. **Name the assumption doing the work**: if it were relaxed, would the prediction flip?
3. **State the prediction with sign, condition, and a rival**: what would a competing model predict instead?
4. **Map to evidence**: which exhibit (event study, first stage, heterogeneity cut) tests it?

## Mechanism language by framework family

| Family | Mechanism wording | Prediction form |
|--------|-------------------|-----------------|
| **Incentives and elasticities** (tax, subsidy, penalty) | "A change in the net return to X shifts the margin at which agents choose X; the response is larger where adjustment costs are lower." | "Outcome falls by about [elasticity] per unit change in the net-of-tax rate; larger where avoidance or substitution margins are cheaper." |
| **Information frictions** (adverse selection, signaling, screening) | "Because quality/risk is private, the uninformed side responds to observable signals; a change in the signal's cost changes who separates." | "When the signal becomes cheaper, the share of [high type] choosing it rises, and the pooled outcome shifts toward [direction]." |
| **Principal-agent / incentives inside organizations** | "The principal cannot observe effort, so pay depends on a noisy outcome; agents shift effort toward what is rewarded and away from what is not." | "Strengthening the reward on measured output raises measured output and lowers unmeasured dimensions." |
| **Market structure and competition** | "Entry changes the markup and the return to innovating; effects depend on distance to the frontier." | "Effect of competition on innovation is positive for firms near the frontier and negative or flat for laggards." |
| **Fiscal federalism and officials' incentives** | "Local officials respond to the criteria on which they are promoted and to the fiscal rules they face." | "Where promotion weights growth, expenditure shifts toward [growth-linked categories]; the effect weakens where [constraint]." |
| **Financial and credit constraints** | "A binding constraint makes investment sensitive to internal funds or collateral rather than to returns." | "Treated firms with tighter constraints respond more; the response disappears for unconstrained firms." |
| **Behavioral** (present bias, inattention, reference dependence) | "Agents under-weight non-salient or delayed components, so equivalent changes elicit different responses." | "A salient change in the posted price/tax elicits a larger response than an economically equivalent included-in-price change." |

## Prediction language (templates)

- **Main**: "Because [mechanism step], we expect [Y] to [rise/fall] in response to [X] among [population]."
- **Heterogeneity**: "The effect should be larger for [group/context] because [the condition that strengthens the mechanism], and absent where [condition that shuts it off]."
- **Channel**: "If the effect works through [channel], we should also observe [auxiliary outcome] moving in [direction]; if it works through [rival channel], we should not."
- **Falsification**: "If the mechanism is [M], a placebo outcome/period/group unaffected by [M] should show no effect."

## Chinese CSSCI wording (理论分析与研究假设)

- 主效应: "基于[机制]，[政策/变量]将[提高/降低][结果]。" → H1
- 渠道: "[渠道]：[政策]通过[路径]影响[结果]，表现为[可观测的辅助变量]的变化。" → H2, H3 (分别检验)
- 异质性: "在[理论上机制更强的条件]下，上述效应更为显著。" → H4
- 避免：只切“东中西”作为唯一异质性；把三步中介当作机制证据。

## Scope of this reference

Pointers are canonical starting points, not a literature review. For a literature search use `/econ-lit-review` (local library first). Treat any model you write as a conceptual frame; a human checks every proof.
